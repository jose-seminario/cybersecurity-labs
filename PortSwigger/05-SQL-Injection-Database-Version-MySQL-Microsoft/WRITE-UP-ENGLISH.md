# SQL Injection — Querying Database Type and Version on MySQL and Microsoft SQL Server

## 📋 Overview

| | |
|---|---|
| **Category** | SQL Injection |
| **Target** | E-commerce web application |
| **Goal** | Retrieve the database type and version via `UNION SELECT` |
| **Databases involved** | MySQL / Microsoft SQL Server |

---

## 1. Lab Introduction

This lab focuses on exploiting a **SQL Injection** vulnerability to retrieve information about the database type and version.

The application is an e-commerce website with several product categories. The objective is to manipulate the `category` parameter and use a `UNION SELECT` attack to retrieve the database version.

## 2. Intercepting the Request with Burp Suite

First, I selected a product category and used **Burp Suite Proxy** to intercept the HTTP request generated by the application.

The request contains the `category` parameter, which is the input to be tested for SQL Injection.

After intercepting the request, I sent the `GET` request to **Burp Suite Repeater** so I could modify the parameter and test different SQL Injection payloads.

## 3. Identifying the Database Context

Since this lab is very similar to the previous Oracle lab, I initially approached it using the same reasoning.

However, the syntax required for SQL Injection can vary depending on the database management system. In the previous lab, Oracle-specific syntax such as `FROM dual`, `BANNER`, and `v$version` was required.

For this lab, the solution instead uses syntax compatible with **MySQL and Microsoft SQL Server**, such as `@@version` and the `#` comment character.

> 💡 **Key insight:** the same technique may need to be adapted depending on the database engine being used.

## 4. Confirming the Number of Columns

Before using `UNION SELECT` to retrieve information, I needed to determine how many columns were being returned by the original query, and which of those columns could contain text.

**Payload used:**

```sql
' UNION SELECT 'abc','def'#
```

The values `abc` and `def` were used as test data rather than actual information from the database.

**Response:**

```text
abc
def
```

This confirmed that the original query returns **two columns**, and that both columns can be used to display text data.

<img width="1345" height="882" alt="image" src="https://github.com/user-attachments/assets/706e0a1d-eff8-48bb-8481-643002ee20a9" />

> ⚙️ **Concept:** a `UNION SELECT` must return the same number of columns as the original query. Since the original query returned two columns, the injected query also needed to return two columns.

---

## 5. Retrieving the Database Version

Once the number of columns and their compatibility with text data were confirmed, I could request information about the database version.

For MySQL and Microsoft SQL Server, `@@version` can be used to retrieve version information.

The injection was structured so that `@@version` was placed in one column and `NULL` was used for the second column, to maintain the required number of columns:

```sql
' UNION SELECT @@version, NULL#
```

**Response:**

```text
8.0.42-0ubuntu0.20.04.1
```

✅ This identifies the database as **MySQL 8.0.42**, with the version information indicating an Ubuntu 20.04 package.

<img width="1462" height="891" alt="image" src="https://github.com/user-attachments/assets/b5fd9567-bd3f-4882-ba89-873b1a8e07f4" />

This demonstrates why understanding the database context is important. In the previous Oracle lab, I had to use Oracle-specific structures such as `v$version` and `BANNER`. Here, `@@version` was the appropriate method.

### 🗝️ Key Takeaways

- `UNION SELECT` requires the same number of columns as the original query.
- Test values such as `abc` and `def` can be used to identify columns that accept text.
- `NULL` can be used as a placeholder when a second column is required but its value is not important.
- Database-specific syntax matters when exploiting SQL Injection.
- `@@version` can be used with MySQL and Microsoft SQL Server to retrieve version information.
- The same SQL Injection methodology can often be adapted to different database engines by changing the database-specific syntax.
